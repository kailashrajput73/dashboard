# Row 2 — core auth schema

## Planned and built

Create PostgreSQL schema only for Mongo collections COL-01, COL-02, COL-03,
COL-04, and COL-07. No Mongo reads, data copy, seed data, auth/login route, or
row-3 taxonomy table was added. Alembic revision `0002_core_auth_schema`
follows `0001_empty_baseline`.

| Mongo collection | PostgreSQL table | Field mapping / notes |
|---|---|---|
| COL-01 `users` | `users` | `id` stays a string UUID. `companyName` → `company_name`; `contactNumber` → `contact_number`; `passcodeHash` → `passcode_hash`; `isActive` → `is_active`; `permissions` stays JSONB. Requester fields `role`, `name`, `phone`, and `address`, and team/admin fields are nullable when not written by that Mongo flow. |
| COL-02 `admin_tokens` | `admin_tokens` | `adminId` → `admin_id`, a real FK to `users.id` with `ON DELETE RESTRICT`; `token` is unique. The Mongo token document has no `id`, so PostgreSQL supplies a string UUID primary key. |
| COL-03 `partners` | `partners` | `id`, `name`, `phone`, `address`, `pincode`, `city`, and `area` retain their names. `businessName` → `business_name`; `salesManager` → `sales_manager`; `documents` stays `documents` JSONB; `kycStatus` → `kyc_status`; `locationVerified` → `location_verified`; `appActive` → `app_active`; `kycHistory` → `kyc_history` JSONB; `rewardPoints` → `reward_points`; `passcodeHash` → `passcode_hash`; `registeredVia` → `registered_via`; `loginCount` → `login_count`; `lastAppLoginAt` → `last_app_login_at`; `approvedAt` → `approved_at`; `approvedBy` → `approved_by`; `reviewedAt` → `reviewed_at`; `reviewedBy` → `reviewed_by`; `rejectionReason` → `rejection_reason`. `phone` has a partial unique index for non-null values, matching Mongo's sparse unique behavior. |
| COL-04 `partner_tokens` | `partner_tokens` | `partnerId` → `partner_id`, a real FK to `partners.id` with `ON DELETE RESTRICT`; `token` is unique. PostgreSQL supplies a string UUID primary key because Mongo token documents omit `id`. |
| COL-07 `money_config` | `money_config` | `adminId` → `admin_id`, a unique FK to `users.id` with `ON DELETE RESTRICT` (REL-02). `discountPercent`, `gstPercent`, `specialDiscountPercent`, `showDiscount`, `showGst`, and `showSpecialDiscount` map to their snake_case equivalents. Defaults are 0, 18, 0, true, true, false, matching the admin-register/auto-provision defaults. |

All five tables have a string `id` primary key, `created_at` and
`updated_at` as `timestamptz` with `now()` defaults, and nullable
`deleted_at`. UUID defaults produce string IDs consistent with `new_id()`;
row 12 must preserve the existing Mongo string IDs. The migration does not
convert any data. At row 12, Mongo top-level `createdAt` and `updatedAt` values
must be parsed to PostgreSQL `timestamptz`; values are not renamed/copied in
this schema-only row. JSONB `permissions`, `documents`, and `kyc_history`
retain their array/object payloads.

## Relationships and auth alignment

- REL-01: `admin_tokens.admin_id` → `users.id`, one-to-many; FK index
  `admin_tokens_admin_id`.
- REL-02: `money_config.admin_id` → `users.id`, one-to-one; unique constraint
  `money_config_admin_id_uq` also indexes the FK.
- REL-03: `partner_tokens.partner_id` → `partners.id`, one-to-many; FK index
  `partner_tokens_partner_id`.
- All three FKs use `ON DELETE RESTRICT`. Token uniqueness is enforced by
  `admin_tokens_token_uq` and `partner_tokens_token_uq`.
- The row-0c queries are unchanged and column-compatible: `ADMIN_TOKEN_SQL`
  selects `users.id`, `users.role`, `users.is_active`, joins
  `admin_tokens.admin_id` to `users.id`, and filters `admin_tokens.token`.
  `PARTNER_TOKEN_SQL` joins `partner_tokens.partner_id` to `partners.id` and
  filters `partner_tokens.token`.
- ORM models live in `backend/app/models/`; Alembic `env.py` imports their
  shared metadata for future autogenerate support.

## DB-STANDARDS checklist for this row

1. **Every new table — applied.** All five tables have a string `id` primary
   key, `created_at`/`updated_at` timestamp-with-time-zone columns, and
   nullable `deleted_at`. Source fields omitted by Mongo creation paths remain
   nullable.
2. **Every relationship — applied.** The three row-2 relationships are real
   id-based FKs with documented `ON DELETE RESTRICT`, plus indexes; the
   unique `money_config.admin_id` constraint supplies its FK index.
3. **Search/filter/sort indexes — applied.** Preserved the row-2 Mongo access
   patterns with indexes for user role/contact/name and partner phone,
   KYC/name, sales manager, and name; token lookup columns are unique-indexed.
4. **Never-repeat values — applied.** IDs are primary keys; both token values
   are unique; partner phone is partially unique when non-null; one config per
   admin is unique. `users.contact_number` remains non-unique because source
   Mongo indexes and mixed-role registration behavior do not define a
   globally unique value.
5. **Multi-table writes — not applicable to this schema-only row.** No
   application write route or Mongo flow is moved here. The optional test
   fixture uses one SQL transaction and rolls it back. Route-level atomicity
   remains for its later route/data-write rows.
6. **Protected API routes — not applicable to this row.** No routes are
   introduced; existing row-0c auth SQL was verified to match these columns.
7. **Incoming-data validation — not applicable to this row.** No request or
   data-copy path is added; the source Pydantic models were read-only
   references.
8. **Audit log — deferred by the migration tracker.** This row adds schema
   only and no business-data create/update/delete path. Generic audit logging
   is explicitly deferred in `migration-db/DB-STATUS.md`.

## Differences and remaining work

This row creates schema only and does not copy or seed any Mongo records.
Token tables gain a required database PK absent from the Mongo token
documents. Soft-delete timestamps are present but no soft-delete route or
filter is introduced. Admin registration/login and partner workflows remain
in `backend_refactor/`; do not use this schema as a cutover until the later
data and route rows are verified.
