# Row 0d — single PostgreSQL backend CORS allow-list

**Status:** Built; user testing remains.

## What was built

- Configured exactly one `CORSMiddleware` in `backend/app/main.py`, with credentials enabled, wildcard methods/headers, and a concrete origin allow-list.
- The default origins preserve the Mongo mirror's local allow-list: `http://localhost:5173`, `http://localhost:3000`, and `http://localhost:8081`.
- `CORS_ORIGINS` adds comma-separated explicit origins. Values are trimmed and de-duplicated; `*` is rejected so credentialed CORS cannot be accidentally opened to every origin. `backend/.env.example` includes the empty setting; add deployment/local origins to the ignored `backend/.env`.
- Added public `GET /api/health` returning `{"status":"ok"}` for browser and preflight checks. No business API routers were mounted.
- Added six standard-library `unittest` cases that exercise the actual ASGI app without a PostgreSQL or MongoDB connection.
- Added Uvicorn as a backend dependency and documented running the new API on port `8001`, separately from the Mongo mirror on `8000`.

## Test and run locally

Use these steps from the repository root. Install `backend/requirements.txt` if this virtual environment has not been updated since Uvicorn was added. Tests require no running database.

### Windows PowerShell

```powershell
py -m venv backend\.venv
backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
Set-Location backend
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Expected: all six CORS tests pass. Start the PostgreSQL API in one PowerShell window:

```powershell
Set-Location backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

The Mongo mirror can continue on port `8000`. In a second PowerShell window, from any directory:

```powershell
$headers = @{
    Origin = "http://localhost:5173"
    "Access-Control-Request-Method" = "GET"
    "Access-Control-Request-Headers" = "authorization,content-type"
}
Invoke-WebRequest -Method Options -Uri http://127.0.0.1:8001/api/health -Headers $headers
Invoke-WebRequest -Uri http://127.0.0.1:8001/api/health -Headers @{ Origin = "http://localhost:5173" }
```

Expected preflight: HTTP 200; `access-control-allow-origin: http://localhost:5173`, `access-control-allow-credentials: true`, and allowed methods/headers including `GET`, `authorization`, and `content-type`. The health GET returns HTTP 200 with `{"status":"ok"}` and the same reflected origin. For a disallowed-origin preflight, replace the Origin with `https://not-allowed.example`; expect HTTP 400 and no `access-control-allow-origin`. Starlette may include `access-control-allow-credentials: true` on its rejected preflight response, but without an allowed-origin header the browser grants no cross-origin access.

To add another explicit local origin, set `CORS_ORIGINS` in `backend\.env`, for example `CORS_ORIGINS=http://localhost:4173`; restart Uvicorn. It is merged with the three defaults. Do not set it to `*`.
