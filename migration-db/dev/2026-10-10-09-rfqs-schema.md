# Row 9 — RFQs schema

## Planned and built

Created PostgreSQL schema for Mongo COL-14 only. Alembic revision
`0009_rfqs_schema` follows `0008_purchases_schema`. This row adds no Mongo
data copy, API routes, dispatch schema, or TXN-17 implementation.

| Mongo field | PostgreSQL field | Notes |
|---|---|---|
| `id` | `rfqs.id` | String primary key; constraint/index name `rfqs_id_uq`. |
| `partnerId` | `partner_id` | Required FK to `partners.id`, `ON DELETE RESTRICT`. |
| `status` | `status` | Required text; indexed with creation time and partner. |
| `grandTotal` | `grand_total` | Required Float for source numeric totals. |
| `specialDiscountPercent` | `special_discount_percent` | Required Float, matching source percentage values. |
| `rewardPoints` | `reward_points` | Required integer. |
| `deliveryMode` | `delivery_mode` | Required text. |
| `scheduledAt` | `scheduled_at` | Nullable text to preserve the source string representation. |
| `history` | `history` | JSONB array, non-null with `[]` default; preserves event action, actor, details object, and timestamp. |
| embedded `lines` | `rfq_lines` | One row per RFQ line. `rfq_id` cascades from its RFQ; `product_id` references `catalog.id` with RESTRICT. |
| line `productCode`, `productName` | `product_code`, `product_name` | Required display copies. |
| line `quantity`, `unitPrice` | `quantity`, `unit_price` | Required Float values. |
| `createdAt`, `updatedAt` | timestamps | Standard `timestamptz` columns with server defaults. Both tables also have nullable `deleted_at`. |

`rfq_lines` are subordinate to the RFQ and cascade on physical RFQ deletion.
The product FK uses RESTRICT to retain the referenced product while quote
lines exist. Soft deletion is represented by `deleted_at`; no hard-delete
route is added here.

## Indexes and deferred work

- `rfqs_id_uq` is the RFQ primary key.
- `rfqs_partner_id` supports partner lookups.
- `rfqs_partner_status` supports partner/status filtering.
- `rfqs_status_created` supports status and newest-first queries.
- `rfqs_created_at` supports newest-first RFQ listings.
- `rfq_lines_rfq_id`, `rfq_lines_product_id`, and
  `rfq_lines_product_code` index line relationships and product-code lookup.
- TXN-17 remains deferred to row 16: approval's RFQ state/history update
  and reward-ledger insert must be in one PostgreSQL transaction.
- Do not add `dispatches`, `dispatch_lines`, or the `source_rfq_id`
  uniqueness constraint here; dispatch schema remains row 11.

## DB-STANDARDS checklist for this row

1. **Primary keys and timestamps — applied.** `rfqs` and `rfq_lines` each
   have a primary key, `created_at`, `updated_at`, and nullable `deleted_at`.
2. **Foreign keys, delete policies, and FK indexes — applied.**
   `rfqs.partner_id` → `partners.id` is `NOT NULL`/`RESTRICT`;
   `rfq_lines.rfq_id` → `rfqs.id` is `CASCADE`;
   `rfq_lines.product_id` → `catalog.id` is `RESTRICT`. Every FK column
   has an index.
3. **Search/filter/sort indexes — applied.** RFQ partner, partner/status,
   status/creation-time, and creation-time paths are indexed. RFQ line
   parent, product-id, and product-code paths are indexed.
4. **Never-repeat constraints — applied for identity.** `rfqs_id_uq` is
   the primary key; no other inventory field requires uniqueness here.
5. **Multi-table transaction — deferred.** No write path was added.
   TXN-17 is explicitly reserved for row 16, which must atomically commit
   the RFQ update and reward-ledger insert.
6. **Protected API routes — not applicable.** No routes were added or
   changed.
7. **Incoming-data validation — not applicable.** No request models or
   API inputs were added.
8. **Audit log — not applicable to this schema-only row.** Runtime
   write-audit behavior remains deferred by the tracker.
