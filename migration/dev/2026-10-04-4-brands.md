# Row 4: Brands

## Planned and built

Migrated the Expo Brands screen to the React web app. The page supports listing, search, active filters, create/edit, logo upload or URL, active toggle, linked products, and passcode-confirmed cascade delete. It composes the shared web components from earlier rows; no packages were added and `frontend/` or `backend/` were not changed.

## How it works

The screen loads brands and catalog products together. Search matches brand names case-insensitively; All, Active, and Inactive filter by `isActive`. Each row shows the brand logo, status, linked-product count, photo action, delete action, and active toggle. Expanding the count uses the same matching rule as Expo: product `brandId` equals the brand ID, or product `brand` equals the brand name case-insensitively. That one page-level matcher supplies both the count and the existing shared linked-product list. The confirmation text remains Expo's exact `Deletes this brand and every product linked to it.`

Creating requires a nonblank name (`Brand name is required.`); create defaults active in the existing API. Editing sends the name, current active state, and logo URL. Photo selection uses the shared web `CoverImageField`; URL entry and removal work through the same component. The status action updates `isActive`, then reloads. Errors continue through the existing API client and ErrorModal.

Deleting calls `POST /api/brands/{id}/delete-cascade` with contact number and passcode. The shared `PasscodeConfirmModal` is prefilled with the signed-in admin contact and requires a passcode of at least four characters. The backend verifies the credentials, deletes the brand, and deletes catalog products matched by brand ID or case-insensitive brand name. After reload the screen shows `Deleted <brand> and <count> product(s).`

## Brand rename ownership

Brand-name propagation is implemented in the backend `PUT /brands/{brand_id}` handler, not in the Expo screen. When a name changes, that handler updates the `brand` value on products that have the matching `brandId`. The web page calls the existing `updateBrand` API wrapper and does not repeat this update.

## Differences from Expo

- React Native layout primitives and `FlatList` are rendered as HTML and inline styles in the web page.
- The shared web `CoverImageField` uses a browser image file input and `FileReader`; Expo uses its document-picker/file-system helper. Both support uploading an image, previewing it, removing it, and entering a URL.
- Brand matching remains in one `productsFor` function in `BrandsPage.tsx` because no shared matching predicate exists in the web pages. The count button and linked list both consume its result. Their UI is reused from the shared `LinkedProducts` component, so Categories and Subcategories are unchanged.
- Rename propagation and cascade deletion remain backend behavior. The web page only calls the existing API wrappers.
