# Row 9: Racks

## Plan

Move Expo's rack list, dimension-based creation, generated slot display, product assignment, and direct delete attempt into the web app. Reuse the existing rack/catalog API wrappers; do not change shared UI or backend code.

## Built

Added the Rack Locations page to the existing web route. It loads racks and catalog products, creates racks from a name and row/column counts, and renders the generated slot codes from the API. Selecting any slot opens product assignment; the Assign product action selects the first empty slot, falling back to the first slot. Deletion calls the existing endpoint directly, and API errors are shown in the shared error modal.

## Expo file to web file

- `frontend/app/(admin)/racks.tsx` -> `web/src/pages/RacksPage.tsx`
- `frontend/src/api/endpoints.ts` -> existing wrappers in `web/src/api/endpoints.ts` for rack listing, creation, deletion, slot assignment, and catalog listing; no API wrapper changes.
- Route registered in `web/src/App.tsx`.

## API calls

Uses `GET /racks`, `GET /catalog`, `POST /racks`, `PUT /racks/{id}/assign`, and `DELETE /racks/{id}`. The list API returns generated slot codes. The existing service generates row letters A-Z and numbered columns, rejects dimensions outside 1-26 rows or 1-100 columns, and rejects deletion while any slot is assigned.

## Differences from Expo

- React Native controls and layout are replaced with semantic HTML, the web UI kit, and inline styles; slot buttons have stable 48-by-44-pixel dimensions.
- The web modal bounds the product list height for scrolling. It keeps Expo's controls, default 3-by-5 dimensions, validation, direct delete attempt, and API error display.
- No backend endpoint, package, or shared component was changed.

## Sync-audit verification (2026-10-08)

Compared the current Expo and web screens after the backend assignment fix. Both send `PUT /racks/{id}/assign` with `{ productId, slotCode }`, refresh racks/catalog after success, and display API errors on failure. Both allow selecting any slot and use the first empty slot (or first slot) from **Assign product**. No rack feature or API change was needed; the existing disposable-data assignment test in `migration/PENDING.md` covers reassigning an occupied slot and verifying the refreshed assignment.
