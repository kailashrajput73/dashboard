# Row 13: Referral Partners

**Status:** Built; manual checks are waiting in `migration/PENDING.md`.

## Built

Migrated Expo `frontend/app/(admin)/partners.tsx` to `web/src/pages/PartnersPage.tsx` and replaced the `/partners` placeholder in `web/src/App.tsx`.

The page provides search, KYC status and manager filters, filtered list export, partner details, reward balance/passbook, purchase history, documents, KYC history, pending-only approve/reject controls with location verification and required rejection reason, and direct admin partner creation. It uses `GET /partners` with the existing `search`, `kyc_status`, and `sales_manager` query fields; partner detail/rewards reads; KYC review; and admin create.

Added web API types for KYC/purchase history and admin create, plus `GET /partners/{id}` and `POST /partners` wrappers. Existing endpoint behavior is unchanged. The export uses Expo's exact 20 headers, row mapping, all-cell quoting, UTF-8 BOM, filtered partner data, and `partners.csv`. No packages, backend, or Expo files changed.

## Expo differences and reasons

- Expo uses React Native safe-area, scrolling/list views, `Switch`, `TouchableOpacity`, and `AppModal`; web uses DOM elements, a browser checkbox, standard links for HTTP(S) documents, and the existing web modal. The same list, form, details, filters, and actions are present.
- Expo opens HTTP document URLs with Linking and reports a Linking failure. Web renders these as standard target-blank links; non-HTTP document paths remain text, matching the Expo branch condition.
- Expo refreshes list data on router focus. Web loads on mount and when search/status/manager filters change; returning to the route mounts and reloads it.
- Expo uses `Platform.OS` and Linking for CSV download; web uses the shared `downloadCsv` helper. File name, BOM, columns, row ordering, quoting, and filtered scope are unchanged.
- KYC, create, list, reward, and detail request bodies/paths and user-facing validation/success/error messages match Expo. No partner feature was found that is unreachable on Expo web, so none is marked decision needed.
