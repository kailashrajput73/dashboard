# Row 16: Team

**Planned:** Port team user list, role filtering, user create/edit, activation toggle, and role permissions display.

**Built:** Added the Team Management page at `/team`. It includes name/contact search, role filters, active/admin/manager/staff counts, permission labels, status toggles, and create/edit modal. Creation requires a four-character passcode; edits update role, contact, active status, and permissions.

**Old -> new:** `frontend/app/(admin)/team.tsx` -> `web/src/pages/TeamPage.tsx`; route in `web/src/App.tsx`; create wrapper accepts the Expo `isActive` field in `web/src/api/endpoints.ts`.

**How it works:** `GET /team/users` loads users. Role changes send that role's default permission list. Create uses `POST /team/users`; edits and activation changes use `PUT /team/users/{id}`.

**API calls:** `GET /team/users`, `POST /team/users`, `PUT /team/users/{id}`.

**Differences from Expo:** Uses responsive React components. Search, roles, payload values, passcode rule, status toggle, and permission labels match Expo. As in Expo, permissions are role defaults/display; this migration does not add route-level role enforcement. Existing-user passcode reset is not supported by the API.

**How to test:** Open Team; search by name/contact; select each role filter; compare summary counts; create a user with name/contact and a four-character passcode; edit role/contact/status; toggle active state and inspect permission labels. Run `npm run build` from `web/`.

**Left:** No role-based route access or existing-user passcode reset is added; both are outside this migration row and the current Expo/API behavior.
